# Cross-Book: cross-venue arbitrage measurement for Kalshi and Polymarket US

Cross-Book (`arb` on the command line) measures price gaps between equivalent
binary markets listed on both **Kalshi** and **Polymarket US**
(docs.polymarket.us; the international Polymarket is out of scope).
**It measures and paper-trades only. No code in this repository can place,
amend or cancel an order.**

The gap between two best prices is not an edge. The edge is what is left after
walking both order books level by level, charging each venue's taker fee on
every fill, and stopping at the first fill that does not pay for itself. The
rest of the system is there so that number can be trusted: one normalized
order book for both venues, a recorder that receives every message before the
parser does, and replay of a recorded run through the same code.

simulated books. No venue, key or database was involved. The amber strip across

## Status: measurement and simulation only

**No code that places, amends or cancels a real order exists in this
repository.** The paper trader simulates fills against measured edges; placing
real orders is a later milestone. [`PROGRESS.md`](PROGRESS.md) tracks the
current milestone and what works.

## The edge walk, in numbers

A made-up ladder, to show the rule. Kalshi offers YES at 40.00¢ for 200
contracts. Polymarket US bids for YES at 48.00¢ for 100 and at 43.00¢ for 100.
Buying YES on Kalshi and NO on Polymarket US (which is selling YES into those
bids) pays $1.00 per contract at settlement whichever way the market resolves,
so a fill's gross is bid minus ask. Both venues charge takers
θ × contracts × p × (1 − p); θ is 0.07 on Kalshi and 0.06 on Polymarket US,
before per-series and per-market adjustments.

| Fill | Kalshi YES ask | Polymarket US YES bid | Contracts | Gross | Kalshi fee | Polymarket US fee | Net | Walk |
|---:|---:|---:|---:|---:|---:|---:|---:|:---|
| 1 | 40.00¢ | 48.00¢ | 100 | $8.00 | $1.68 | $1.50 | +$4.82 | takes it |
| 2 | 40.00¢ | 43.00¢ | 100 | $3.00 | $1.68 | $1.47 | −$0.15 | stops here |

The top of book says 8¢. The walk reports 100 contracts at 4.82¢ net each.
Added together the two fills would still show a profit ($11.00 gross against
$6.33 of fees), which is why the stop rule judges each fill on its own gross
and its own fees. The second hundred loses 15¢ and is refused. Each row is a
case in
[`tests/test_fees_edge.py`](tests/test_fees_edge.py):
`test_eight_cent_gross_nets_after_fees` is the fill that is taken and
`test_fees_can_erase_a_three_cent_gross` is the one that is refused.

The walk is `compute_direction()` in [`src/arb/edge.py`](src/arb/edge.py), run
in both directions for every tracked pair. Prices and sizes are integers and
the fee formulas in [`src/arb/fees.py`](src/arb/fees.py) are evaluated with
`fractions.Fraction`, then rounded by each venue's documented per-fill rule:
Kalshi up to the next tick, Polymarket US half-even to the cent. Two documented
refinements are not modelled: Kalshi's sub-tick rebate
([`docs/engine.md`](docs/engine.md#kalshi)) and Polymarket US's cap on
cumulative rounding
([`docs/venue-notes.md`](docs/venue-notes.md#fees-for-the-arb-math)). Either
one would only lower the fee charged. The full walkthrough is in
[`docs/engine.md`](docs/engine.md#edge-the-depth-aware-two-direction-walk).

## What else is worth opening

- **One order-book model for both venues.** Prices are integer ticks of
  $0.0001 and quantities are integer units of 0.0001 contracts, because live
  Kalshi books carry fractional counts ([`src/arb/types.py`](src/arb/types.py)).
  Kalshi publishes bids only, for YES and for NO, so
  [`venues/kalshi/ws.py`](src/arb/venues/kalshi/ws.py) folds a NO bid at *x*
  into a YES ask at 10000 − *x* before shared code sees it. A
  [`Book`](src/arb/book.py) is valid only while it has a snapshot with no
  sequence gap since, is not crossed, holds only positive quantities at prices
  inside (0, 10000), and updated within the staleness limit. The paper trader
  declines any edge that rests on a structurally invalid book.
- **Record before parsing, replay through the same code.** Every raw message
  is stamped (`recv_ts_ns`, `recv_mono_ns`, `run_id`, `ingest_seq`) and
  enqueued for [`src/arb/recorder.py`](src/arb/recorder.py) before it is
  parsed. The enqueue never blocks ingest: overflow is dropped and counted, and
  a failing sink is retried in place with its batches kept in order.
  [`src/arb/replay.py`](src/arb/replay.py) reads a run back in `ingest_seq`
  order through the same adapters and `BookManager`, on the recorded monotonic
  clock.
- **Pair matching ends with a person.**
  [`src/arb/pairs/matcher.py`](src/arb/pairs/matcher.py) scores event pairs by
  IDF-weighted title similarity plus outcome overlap: how many of one event's
  outcomes have a name twin on the other venue. Rules text is left unscored on
  purpose. Whether two markets resolve the same way is decided by their rules
  text, which a person reads on `/pairs` ([`docs/pairs.md`](docs/pairs.md)).
- **Every control goes through one executor.** `ControlPlane.execute()` in
  [`src/arb/ui/control.py`](src/arb/ui/control.py) validates, states the effect
  as a sentence, refuses if read-only, arms or confirms, applies, and audits.
  Actions that need confirming are confirmed server-side, with a single-use
  90-second token bound to a SHA-256 of `(action, params)`. Arming writes an
  audit row before the token is issued, and if that write fails there is
  nothing to confirm.
- **A keyboard model that came from a bug.** Typing `RUN` on `/pairs` once
  fired `R`, `U` and `N` as hotkeys and wrote two rows to Postgres. Key scope
  is now derived from `document.activeElement` on every keydown, so a bare
  letter always goes to the `ARB>` command line and a page's single-letter
  keys fire only while its row list has focus
  ([`docs/decisions.md`](docs/decisions.md#m19--the-keyboard-gets-a-focus-model-and-keys-get-a-price),
  [`core/keys.js`](src/arb/ui/static/js/core/keys.js)).
- **Tests run against real payloads.** Parser tests use captured venue
  payloads in [`tests/fixtures/`](tests/fixtures), and `hypothesis` covers the
  book and the fixed-point types. The frontend has a unit suite on node's
  built-in runner (no `package.json`) and an acceptance suite that drives the
  real frontend in headless Chrome over CDP. The frontend tests were
  mutation-tested, and two that could not fail were rewritten.

## Run it

### Without credentials

The preview serves the real FastAPI app and the real static frontend over
simulated books. It needs Python 3.12+ and [uv](https://docs.astral.sh/uv/),
and nothing else: no `.env`, keys, Postgres or Docker. It contacts no venue.

```sh
uv sync
uv run python scripts/preview_ui.py              # http://127.0.0.1:8765
uv run python scripts/preview_ui.py --failures   # adds a seq gap and a crossed book every 40 s
```

Kalshi books stream small deltas and Polymarket US books arrive as whole-book
polls, as the real feeds do. The preview does not simulate tracked pairs, so
`/arb` shows its empty state, and the paper-trading, watch-set and database
figures on `/system` and `/control` are constants the preview seeds.

![MONITOR refusing a crossed book, under an amber strip reading SIMULATED DATA: the depth banner reads INVALID, CROSSED, BOOK UNTRUSTED UNTIL RESYNC; the mid is replaced by the word CROSSED with BID 12.00 at or above ASK 11.00; the depth chart and ladder are greyed out](docs/img/monitor-crossed.png)

*A crossed book, injected by `--failures` into a simulated Kalshi book. The
bid sits above the ask, so the book is marked invalid, greyed out and
untrusted until a resync.*

### The full stack

This needs venue API keys, Docker and a filled-in `.env`.

```sh
cp .env.example .env                               # fill in; .env is gitignored
docker compose up -d postgres prometheus grafana   # each bound to 127.0.0.1
uv run alembic upgrade head                        # required: every control action is audited to Postgres
uv run arb doctor                                  # env, keys, clock skew, database, venues, disk
uv run arb ui                                      # http://127.0.0.1:8080
```

Plain `docker compose up -d` also starts the app in a container on the same
port 8080, so use one or the other
([`docs/ops.md`](docs/ops.md#bringing-the-stack-up)). The UI has no
authentication: it binds to `127.0.0.1` and refuses any other host unless
`ARB_ALLOW_REMOTE_BIND=1` is set
([why](docs/ops.md#binding-beyond-loopback)).

`arb ui` serves a keyboard-driven terminal with one URL per page: `/`
(MONITOR), `/arb`, `/pairs`, `/paper`, `/system`, `/control`, `/help` and
`/market/<id>`. `/control` is the operating surface: recorder on and off, paper
trading suspend, resume and risk limits, each venue's market universe, the
watch set of tracked pairs, and the jobs (doctor, pair proposal, link backfill,
replay). `arb ui --read-only` serves every page and refuses every mutating
control; DOCTOR still runs, and pair decisions on `/pairs` are not covered
([limits](docs/ops.md#read-only-mode)). The other two commands are
`arb doctor`, for when the UI will not start, and `arb replay`, which is also
the worker the REPLAY control spawns. Pages and keys are in
[`docs/ui.md`](docs/ui.md), flags in [`docs/cli.md`](docs/cli.md).

### Checks

```sh
uv run pytest                          # add -m "not browser" to skip the headless-Chrome tests
node --test "tests/js/**/*.test.mjs"   # frontend unit suite
uv run ruff check .
uv run pyright
```

There is no CI yet, so these are run by hand;
[`docs/testing.md`](docs/testing.md) records that gap.
